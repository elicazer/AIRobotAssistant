# sounddevice audio transport for macOS OpenAI Realtime sessions

The change replaces PyAudio with sounddevice raw streams for OpenAI microphone capture and speaker playback while preserving the 24 kHz mono PCM contract, 100 ms capture chunks, 40 ms playback slices, and lip-sync callback path. It adds a pinned sounddevice dependency, changes the checked-in devices, and folds the behavior into a broad README rewrite. The fix is not ready to ship because its advertised fallback does not retry the system default when opening a nominally valid configured device fails, and none of the new native-audio behavior is covered by tests.

Watch for: **confirmed — blocking:** stream-open failures bypass the fallback and leave the session without capture or playback; **confirmed — blocking:** no tests exercise raw stream I/O, fallback, or cancellation; **likely:** queued animation callbacks can make shutdown block the event loop; **likely:** PyAudio-produced device indexes are consumed by a separately loaded PortAudio wrapper.

**Verdict**: NEEDS_CHANGES

## High-level view

OpenAI audio now bypasses the PyAudio extension implicated in the macOS crash and uses sounddevice raw streams directly. The byte format remains compatible with the existing queue and mouth-animation pipeline, but **confirmed:** fallback is decided before stream open, so runtime open failures never retry the default device.

The capture and playback tasks remain under the existing session loop. Cancellation aborts native streams before joining workers, but **likely:** playback can accumulate animation work in an unbounded single-worker executor and synchronously drain it during cleanup, stalling the event loop.

Device selection remains owned by the PyAudio-backed `/api/devices` endpoint and is persisted as an integer. **Likely:** two separately packaged PortAudio wrappers can expose different ordering; **confirmed:** the new checked-in indexes also encode one machine’s hardware despite the README recommending `null` for portability.

The exact sounddevice dependency is present, but **confirmed:** documentation still describes indexes and troubleshooting as PyAudio-only. **Confirmed — blocking:** the native-audio path has no dedicated tests, while **confirmed:** a full README rewrite and unrelated repository changes make the crash fix harder to isolate and roll back.

### Raw stream setup stops fallback before the failure-prone operation

`_resolve_audio_device()` only proves that a configured index can be queried and advertises at least one channel (`src/openai_realtime_client.py:495-511`). **Confirmed — blocking:** a device can pass those checks and still fail when the raw stream opens or starts because it was disconnected, is busy, rejects 24 kHz mono `int16`, or refers to a different endpoint in sounddevice’s index space. Construction at `src/openai_realtime_client.py:536-544` and `src/openai_realtime_client.py:589-598` then falls into the broad task-level exception handler; there is no second attempt with `device=None`.

```text
configured integer
       │
       ├─ query fails / no channels ──> device=None ──> open default
       │
       └─ query succeeds ─────────────> open configured ──X─> log and stop task
                                                        no default retry
```

Move construction behind an open helper that validates the complete format with `check_input_settings()` or `check_output_settings()`, catches `PortAudioError` from construction/start, and retries once with `device=None`. If both attempts fail, surface a terminal session error rather than allowing the audio task to disappear behind a log message.

### Callback draining can make cancellation wait without a bound

Capture has at most one executor read in flight, and playback awaits each executor write. **Likely:** the callback path differs: every 40 ms slice submits fire-and-forget mouth/viseme/servo work to one worker (`src/openai_realtime_client.py:640`), with no retained future or queue bound, then cleanup calls `cb_executor.shutdown(wait=True)` synchronously on the asyncio thread (`src/openai_realtime_client.py:652-653`). If processing falls behind real time, Stop waits for every stale animation callback while the event loop cannot advance; the server’s five-second cross-thread timeout cannot interrupt that synchronous drain.

Keep at most one pending animation callback or drop stale callback work, cancel queued futures during shutdown, and run any required executor join off the event-loop thread. Handle the awaited stream-write worker separately from disposable visualization callbacks.

### PyAudio device selection crosses into sounddevice by integer

The browser gets devices from PyAudio (`src/mouth_visualizer.py:97-108`), and the server passes the persisted integers directly to OpenAI (`src/voice_assistant_server.py:359-360`). **Likely:** ordering can diverge when PyAudio and sounddevice load different PortAudio builds or host APIs, turning a valid UI selection into the wrong endpoint or an open failure. Both wrappers enumerated the same five devices in the same order on the reviewed Mac, which verifies only that environment.

Use sounddevice enumeration for OpenAI sessions, or persist host API plus device name and resolve it inside the active provider. At minimum, validate the full 24 kHz format and log the resolved name and host API before opening.

### Shared settings and docs contradict the fallback story

The committed settings switch to microphone `1` and speaker `3` (`config/voice_assistant_settings.json:3-4`). **Confirmed:** these map to `DJI MIC MINI` and `MacBook Pro Speakers` on the reviewed Mac but remain machine-specific, while the new README example uses `null` and warns that checked-in indexes may not exist elsewhere. Set both shared values to `null`; keep local selections outside the repository or persist them through the UI at runtime.

**Confirmed:** although `requirements.txt:53` adds the required sounddevice pin, the README calls the persisted values “PyAudio device indexes,” gives only PyAudio/PortAudio installation and troubleshooting guidance, and directs OpenAI users to a PyAudio-backed device endpoint (`README.md:121-127`, `227`, `470`, `478-480`). State that Nova and device discovery use PyAudio while OpenAI capture/playback use sounddevice, and add sounddevice-specific import/open diagnostics.

### Native audio behavior has no regression coverage

No test file changes in this diff, and the test tree contains no references to sounddevice, `RawInputStream`, `RawOutputStream`, `capture_audio`, `play_audio`, device resolution, or output latency. **Confirmed — blocking:** the macOS crash fix has no automated check for buffer conversion, 40 ms write slicing, configured-device fallback, cancellation during a blocking read or write, abort/close ordering, or executor cleanup. Add mocked sounddevice tests for successful I/O, configured-open failure followed by default success, both-open failure, cancellation, and bounded callback cleanup without requiring audio hardware.

### README and asset churn obscure the crash fix

The README grows from 292 to 576 lines and rewrites architecture, credentials, hardware, tools, testing, and project structure beyond the sounddevice change. **Confirmed:** the same local diff also ignores `tmp/` and deletes `templates/avatars/sample.vrm`; neither is required to replace the OpenAI audio wrapper. Split focused audio documentation and tests from broader documentation and asset cleanup.
